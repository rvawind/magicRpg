## 背景

将 Forest 关卡的 13 房间有向图 + 3 秒引导传送，替换为 7×7 网格 Roguelike：
清房才能移动、紧急穿越技能、20 + 1 物理槽位池、信息揭示、曼哈顿诅咒 + 候选 BOSS 房。

## 已锁定决策

1. **方向由位置决定**：每房间 4 个方向矩形（上下左右），各带特效。
   - 传送统一由共通技能触发：站进方向矩形施法 → 瞬时传送（Step 3.6 起走进矩形不再自动传送）
   - 清房后（安全/入口/已清空）：免费，不扣血、不进冷却
   - 未清房：紧急穿越，扣 20% 当前生命；濒死免费但 10s 冷却
2. **传送门 = 矩形 + 特效**：矩形只用于方向判定与特效，不监听走进事件。
3. **类型/奖励预分配**：保留 InitArea 遍历分配。
4. **怪物池持久化**：spawned/killed/alive 跨进入累积，离场删怪断点续刷。

## 各步要点

### 第一步
- `exit.j`：入口矩形检测加「源房已清空或安全区」闸门；停留时长可配置；清房后刷新出口特效。
- `monster_room.j`：`OnRoomCleared` 内调用 `RefreshAreaExitState(areaId)`。

### 第二步
- 新增共通技能：站方向矩形放技能→穿越；代价 20% 当前生命 / 濒死免费但 10s 冷却。
- `monster_room.j`：离场杀怪（保留游标），复入断点续刷。

### 第三步（已实现）
- 新增 `grid.j`（7×7 网格模型）与 `slot.j`（20 槽位池：4 地形 × 5）。
  生成流水线：生成树（保证连通）→ 额外边预算（braid 死路 + 随机环路）→ 连通断言；
  生成策略可经 `Grid_SetGeneratorMode` 替换（详见 `优化清单.md` O6）。
- `data.j`：逻辑 ID 持久数据、`Area_EnsureBound`（同地形槽位分配）、外围 8 起点与 BOSS 候选。
- `enter.j`：按槽位常驻触发器，逻辑 ID 记账；空闲槽位定时回收（CLEARED/INACTIVE 且无玩家）。
- `exit.j`：门洞矩形只作方向判定与特效（Step 3.6 起走进不传送），传送统一由技能调用 `TryTraverse`；
  无邻居方向用 `SetTerrainPathable` 动态阻断路径（释放/重绑/重置时恢复），
  **不加任何红色特效**（红色专指「有路但未清空」），只把门洞模板矩形内的可破坏物克隆过来当视觉障碍；
  模板里没摆东西的方向就保持空门洞。
  原始路径状态在方向首次封锁时懒采样，避免初始化线程超过 JASS 单线程字节码上限。
- `monster_room.j`：刷怪点用 `NNCIsWalkAble`（地形 + 可破坏物）检测，随机取样失败后网格扫描兜底；
  刷怪按每批 2 只重新武装计时器，避免单线程越过 JASS 字节码上限。
- `monster_room.j`：怪物池按逻辑 ID 持久化，槽位释放时清理实例并回退游标。
- `forest.j`：替换为网格配置；物理房按 `gg_rct_FR_*` 命名注册，门洞矩形自动生成。
- `chapter.j`/`dust.j`：适配新的初始化与重置顺序。
- **已就位**：20 个房间矩形 `gg_rct_FR_A1..A5 / B1..B5 / C1..C5 / D1..D5`
  与 16 个门洞模板矩形 `gg_rct_FR_{A,B,C,D}_DOOR_{UP,DOWN,LEFT,RIGHT}` 已在 WE 中创建并通过本地预编译。
- **验收结论（2026-10-27）**：`测试.md` Step 3 通过；验收期间的四个行为确认：
  ① 首次进房 `待刷N` 等于该房怪物组总量属正常；② 传送落点为目标房「通往源房」的门洞中心；
  ③ 门洞只作方向指示，传送统一由共通技能发起（清房后免费）；④ BOSS 中转房按逻辑 ID 回调、不刷怪。
- **测试期干扰项**：地图自带触发器 `Init_Base` 在地图原点 (0,0) 创建 40 个 `'Obla'`（剑圣）占位单位，
  而 (0,0) 落在物理房 `FR_D5` 内，看起来像「房间刷出一堆剑圣」。与本系统无关，
  建议作者把这些占位单位的创建点移出 20 个物理房范围。
- **生成器调整（2026-10-27）**：`prune` 概率改为「额外边预算」——
  Forest 为 48 条生成树 + 10 条额外边 = 58 条边；braid 概率 0.60；
  入口与 BOSS 的图距离目标 8（无候选满足时取最远入口）。候选的多支路方案见优化清单 O6。
- **字节码上限修复（2026-10-27）**：`Grid_GetDistance` 每次调用都跑一遍 BFS，
  `RollActiveEnter` 对 8 个候选逐个查询导致初始化线程超限。改为
  `Grid_BuildDistanceField` + `Grid_GetFieldDistance`（一次 BFS、O(1) 读取），
  并把 `InitForest` 拆成两段：`InitForest`（物理房 + 网格 + 逻辑房 + BOSS 抽签）→
  `TriggerExecute` 跑 `InitForestStage2`（入口抽签及后续全部）。同步执行，初始化顺序不变。
