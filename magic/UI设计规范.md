# 地图 UI 设计规范（现行）

> **版本：v2.0（2026-11-17 整合）**　适用：`magic/map/ui/gridMap.j`
> 本文件只描述**当前实现**；旧 F10 金框 / v1.x 论文案已全部废止，不再保留。
> 参考像素：1100×568；换算：`ux = px × 0.8 / 1100`，`uy = px / 946.6667`。

## 1. 外观与结构
实体羊皮纸地图：整幅烧边纸面，标题单行居中，右侧信息卡 + 纸上图例，无副标题/统计/小队文字/罗盘/独立图例卡。
所有元素均为「预烘贴图 + 文字色 + frame alpha」；BACKDROP 顶点色无效，文字左对齐手算（TextAlignment 无效）。

## 6. 贴图（BLP，30 个）
- 纸 `map_paper.blp` 658×356；信息卡 `map_card_info.blp` 444×216(2x)。
- 格贴图 15 个：`map_cell_{unexplored,unknown,plain,monster,safe,boss,entry,elite,merchant}`（后 6 类各含 `_cleared`）92×68(2x)。
- 环/封印：`map_current_ring`、`map_hover_ring` 104×84、`map_wax_seal`、`map_gold_seal`。
- 徽记 8 个：6 房型 + `map_em_unknown_pale`、`map_em_check`。
- 透明按钮：`ui\blank.blp`。
- 格式：BLP1（compression=1、paletted+alpha list）；源 TGA 在 `.team/ui_design/design_v3/web_assets_final/ui/`，转换器 `.team/tools/convert_tga_to_blp.py`。
- 导入包：`dist/UI_BLP_v1.5_20261117.zip`。

## 7. 交互
- `~`（VK_OEM_3=192）开关面板；打开/关闭走 `ApplyVisible`，关闭时复位缓存。
- 悬停：每格透明 `GLUEBUTTON` + `DzFrameSetScript` 事件 **2/3**（enter/leave）+ `DzGetTriggerUIEventFrame()` 映射到具体格；悬停只改本地显示、不同步。
- 若日后加会改变游戏状态的点击，必须按作者选英雄触发的同步写法（`DzSyncData` + 同步触发器）。
- 刷新：0.5s 变化驱动（缓存比较），仅状态变化时调 Dz 接口。

## 10. 视觉验收（美观自检，门禁 G-UI 依据）

> 目的：把「美观」变成可判定的硬指标，交付前自检；**任一项 FAIL 不得交付**。
> 作者只裁决风格偏好（配色/气质/方案选择），不负责替你发现溢出、拥挤、遮挡这类基础缺陷。
> 背景：2026-11-17 task-16 出现「字体溢出框、左右留白失衡、整体拥挤/空旷」被作者退回，本清单据此沉淀。

| # | 检查项 | 可执行判据 | 证据 |
|---|---|---|---|
| 1 | **文本不溢出** | 每个文本帧：估算 `textW ≤ 帧宽 − 2×内边距`（信息卡内边距 12；图例列宽 111；状态行按 v1.6 x 偏移 0/70/140、行尾右距≈48）。超出时**先缩文案**（§4：13 字/行），再考虑换行/缩短标签；禁止出框。状态行「未领取/已清/未探」与图例标签必须逐项核对。 | 截图 + 实测 textW 值 |
| 2 | **不遮挡** | 内容不越安全区 (32,25)-(626,331)；不压右上原生「出发时间」HUD、底部控制台/游戏信息区；面板打开时 HUD 仍可见。 | 全屏截图 |
| 3 | **留白平衡** | 左右/上下对应留白差 ≤ 8px；元素与纸边距不小于 §8 表值（网格底 17、卡右 16、状态行右 26/底 23、标题顶 21）；除纸面烧边外，不得出现 >40px 的无意义空白块。 | 截图 + 测量值 |
| 4 | **密度合理** | 不为塞信息而缩字号、压行距、贴边；主区与右栏宽度比按 §3/§4（网格 358 : 右栏 222）；内容多时优先减信息（§1：无副标题/统计/小队文字）。 | 截图 + 取值 |
| 5 | **对齐** | 同列左缘同一 x；标题按 `textW/2` 居中，误差 ≤2px；图例行与状态行同基线；信息卡内各行左缘一致。 | 截图 + x 坐标 |

| 10 | **整体观感** | 交付前把截图按“一个第一次玩的人”的视角看一遍：能否一眼读出「我在哪格、这格是什么、整体是什么」。做不到就不算完成。 | 自检结论一句话 |

### 10.1 交付前自评（AI 必须先看图，再决定交不交）

- **强制步骤**：UI 批次完成后、交付前，必须用图像读取工具打开**最新实机截图**（至少三态：默认 / 悬停 / 状态变化），逐张自评；**不得只把截图当证据贴上去就交付**。
- **输出格式**（写进交付消息与门禁报告）：
  - `结论：PASS / FAIL`
  - `缺陷清单`（≥3 条，或 PASS 时说明为什么没有）：位置 + 现象 + 建议改法
  - `第一眼测试`：第一次看到这张图，有没有一眼就觉得突兀/廉价/像调试界面的元素？
- **FAIL 即不得交付**：先改 → 重新截图 → 再自评，循环到 PASS；禁止把「请作者看看」当作验收手段。
- **第一眼直接 FAIL 的信号**（不需要专业审美）：调试框/硬边高亮；纯白卡片贴在纸面上；明显未对齐；大面积无意义空白；文字糊、小到看不清；图标风格混用（线稿 + 彩色徽记）；同一面板两种材质；疑似错别字。
- **责任边界**：作者只裁决**风格偏好**（配色/气质/方案选择）；溢出、遮挡、对齐、空白、糊、错字等基础缺陷属于 AI 自评责任。
- **自动化现状（2026-11-23 更新）**：`tools/ui_screenshot_check.py` **已停用**——它依赖的 `[gridmap] rects` 诊断行随 `LogRects()` 一起移除（窗口 API 在 UI 初始化时导致 Game.dll 崩溃，见 `magic/fixes/2026-11-23-ui-logrects-crash.md`）。停用前状态（2026-11-21）：实验版，固定坐标/亮度投影在实机截图上标定不可靠（烧边被算成内容、白卡与纸面高光难区分），`暂不作为门禁依据`。替代方向：用安全常量/配置值，或延后到独立、可禁用的诊断开关，在作者图实测通过后再启用。
