# 代码质量基线（magic/ 专有代码）

> 把「符合软件工程」翻译成本仓库**可判定**的检查项。
> 使用方式：Lead 编码时自检；verifier 用本文件做门禁与架构复核；作者做最终裁决。
> 版本 **v0.7**（2026-11-21），依据 Phase 0 校准 + UI 批次审计 + 视觉验收补齐 + 任务完成契约/审查分级 + 技能 A/B 两轮增量（见第 7 节变更记录）。

## 0. 责任模型

| 层 | 责任人 | 职责 |
|---|---|---|
| 设计与实现 | **Lead** | 代码质量第一责任人：模块划分、接口、可测试性、文档同步 |
| 独立检查 | **verifier** | 按本文件输出 PASS/FAIL + `文件:行 + 规则号 + 证据`；只报不改 |
| 最终裁决 | **作者** | 产品意图、行为正确性、P1 取舍的最终决定 |

原则：**写和查必须分离**。verifier 不修代码；Lead 不给自己开绿灯。

## 1. 严重级

| 级别 | 定义 | 处理时机 |
|---|---|---|
| **P0 阻断** | 编译失败；违反 A 类硬规则；破坏全局不变量；字节码/线程预算风险；**确定性**的句柄/触发器泄漏 | 修复后才能同步与进入游戏验收 |
| **P1 应修** | 违反 B 类工程基线；接口与文档漂移；验收项不可观察；可维护性明显受损 | 本步内修，或登记技术债（Lead 裁决，每步汇报给作者） |
| **P2 建议** | 风格、可读性、注释、命名细节 | 只登记，不阻塞 |

## 2. 检查清单

### A 类：硬性 / 防错（P0）

- **A1 编译**：`python tools/precompile_check/build_harness.py` + `run.bat` 后，`out/compile.log` 出现 `Success!` 与 `EXIT=0`。
  - **执行环境**：`run.bat` 要求对 `KKWE\plugin\jasshelper` 有写权限（`clijasshelper` 必须在该 cwd 写 `backups/`、`logs/`）。受限沙箱下的**等价验证**：把同一套二进制只读复制到 `tools/precompile_check/out/jh/`，`PATH` 前置 `KKWE\bin`，在该目录执行同一命令；canonical `run.bat` 日志由 Lead 在完整权限下补跑。
- **A2 命名**：库名 camelCase 无下划线；**本仓库自身声明的**变量禁用 `udg_` 前缀，变量名避开保留字（`code`/`type`/`function` 等）。
  - **GUI 互操作例外**：WE 触发器生成/使用的 `udg_*` 全局（如 `udg_Hero`）允许被引用，但必须在代码注释或 HANDOFF 说明来源与生命周期。
- **A3 include**：写**编译后路径**（`nncou\\magic\\...`；`core/` 与 `japi/` 文件从 `jass/` 根引用，`japi\\...` 允许）；文件自带 `#ifndef/#define/#endif` 守卫，外层不重复包裹。
  - **`#endif` 空行**：仅当同文件在 `#endif` 之后还有代码时才要求空行；文件以 `#endif` 结尾不加空行（与全仓现状一致）。
- **A4 前向引用**：函数定义在调用点之前（vJass 单遍扫描）；跨库调用 `public` 函数必须带库名前缀。
- **A5 句柄生命周期**：
  - 创建型句柄（`unit`/`group`/`timer`/`effect`/`trigger`）在函数末尾置 `null`，不再使用的 `trigger`/`timer` 必须 `DestroyTrigger`/`DestroyTimer`；需要时 `RemoveSavedHandle`。
  - **重复初始化路径**（章节切换、`Reset*`、重注册）不得每次重建常驻触发器/计时器而不销毁旧的。
- **A6 无效 ID**：areaId 判无效必须 `< 0`（`FOREST_A` 的合法值为 0）。
- **A7 日志分级**：TRACE 高频过程 / INFO 低频结果 / WARN 不变量被破坏；不得用全局 `debug_level = -1` 作为排查手段。
- **A8 第三方边界**：不改 `core/` 下 YDWE/平台/Blizzard 代码；通用能力进 `core/nncou/`，专有玩法进 `magic/`。
- **A9 预算**：新增初始化逻辑不得引入逐房 BFS / O(N²)；批量查询用距离场（`Grid_BuildDistanceField`）；大循环分批或 `TriggerExecute` 拆线程。
- **A10 生成物**：`magic/map/attr/**` 与 `magic/map/equip/baseItem/{data,text}/**` 由脚本生成，改源 CSV/Lua 后重跑生成器，不手改产物。

### B 类：软件工程（P1）

- **B1 依赖方向**：
  - `config` → `core` → 新模块；`magic` 单向依赖 `core/nncou`；禁止反向依赖与跨层回调。
  - **分层白名单**：`area/core/`、`map/timer/` 等通用框架**不得 `requires` 具体玩法模块**（如 `ChapterTimer`、`RewardAltar`、`CurseSystem`）；跨层一律「私有钩子置空 + config/ChapterManager 注册回调」；扩展点用既有钩子（如 `AddAreaEnterCallback`）。
- **B2 接口对称（可判定）**：有 `Init` 的系统必须有 `Reset`，且 **Reset 逐项覆盖正常路径写入的每一类状态**（标量、逐房标记、列表/候选队列、计时器、句柄）；新增系统提供只读查询接口，查询幂等。
- **B3 复用先于新增**：新增 API 前先查 `core/nncou` 与既有模块是否已有等价能力（例：`NNCIsWalkAble`）。
- **B4 职责边界（量化）**：一个库/文件单一职责；文件 > 38KB 后禁止新增非查询逻辑，新增只读查询须登记技术债并在汇报中说明；优先新文件 + 钩子。
- **B5 数据/行为分离**：数值与配置进 `config/`；行为进 `core/`；不把关卡数值写死进框架。
- **B6 死代码/重复**：不保留注释掉的旧实现；不复制粘贴重复逻辑；新逻辑取代旧逻辑时删除旧代码。
- **B7 diff 范围**：一次改动只做一件事，不夹带无关格式化/重命名。
- **B8 可测试性**：新行为必须有可观察证据（INFO 日志 / 调试探针 / 查询接口），能对应到 `magic/测试.md` 验收项；**调试接口必须定义边界状态取值**（未开始/进行中/cap 已满/已清空），测试项写清期望值。
- **B9 错误处理**：不变量被破坏时打 WARN 并保持可继续运行；不允许静默吞掉异常状态。
- **B10 UI token 单一来源（2026-11-16 新增）**：`magic/map/ui/**` 的视觉参数（尺寸/颜色/alpha/字体/时序）必须 1:1 对应 `magic/UI设计规范.md` 的 token 表；token 外只允许「合理常量」（VK 码、锚点枚举、alpha 255、px 换算公式、数学因子）。**先改规范、再改代码**；禁止用截图试出来的裸字面量直接进代码而不回写规范。新增 UI 文件必须同步 `build_harness.py` 的 `SOURCES` 并过 UI 门禁。

- **B11 章节地图规格单一数据源（2026-11-17 新增，P0/P1）**：`magic/` 下的**核心/UI/测试代码与文档**不得写死章节地图规格；地图规格的唯一定义是**章节配置**（`area/config/*.j`）。
  - **B11.1 规格定义**：地图 = **房间集合**（cell 坐标 (row,col)，可稀疏：允许缺格/洞/L 形/十字形，**不是满矩形**）+ **边列表**（**只允许上下左右 4 向邻接**，未连通方向按策略剪枝，缺格方向无门）+ **章节参数**（包围盒/缺格集合/边预算/房间类型配比/物理槽位数/时间/侵蚀参数等）。
  - **B11.2 单一数据源**：除章节配置文件外，具体数值与坐标/边/数量一律不得复制；必须从 API 推导：`Grid_GetCellCount()`/`Grid_GetTotal()`（实际房间数）、`GetAreaCount()`/`GetAreaByIndex()`、`Grid_GetNeighbor()`/`Grid_GetRow()`/`Grid_GetCol()`、`Grid_GetEdgeCount()`、`Slot_GetCount()`、`Slot_GetTerrainTypeCount()`、`Grid_GetBoundingRows()/Cols()`。查询接口不存在时先补接口，不得用字面量代替。
  - **B11.3 禁止（可机械判定）**：① UI/测试/文档中出现 `7×7`/`6×6`/`49`/`58`/`20`/`36` 等具体规格数字（文档仅在带「当前样例」限定语时允许）；② 非 `grid.j` 代码出现 `row*cols+col`/`*7+`/`Grid_Init(数字,数字)` 一类算式；③ UI/测试遍历「所有房间」用 `for i=0..Grid_GetTotal()-1` 且无「该格是否存在」判断；④ 测试用具体数量/日志子串（如 `edges=58`、`slots=20 terrains=4`）做断言，而不是与同一 API 实际值比较。
  - **B11.4 允许（合理常量）**：章节配置的具名常量与 cell/边/参数表；UI 视觉 token（px/字号/alpha/颜色/帧尺寸）；`DIR_*`/`ROOM_TYPE_*` 枚举与循环下标/-1；测试自洽断言（同一 API 两次读数比较、日志解析后与 API 比较、0/-1/类型枚举）。
  - **B11.5 语义约定（迁移必做）**：`Grid_GetTotal()` = **实际存在的房间数**（稀疏时 ≠ 包围盒面积）；`Grid_GetId(row,col)` 仅对存在格返回有效 id；遍历房间用 `Grid_GetCellByIndex()` 或 `GetAreaByIndex()`；包围盒单独查 `Grid_GetBoundingRows/Cols()`；边总数查 `Grid_GetEdgeCount()`。测试期望值必须来自配置 cell/边表或上述 API 自洽值，不得用具体数量字面量。
  - **B11.6 例外**：`.team/` 下设计稿/评审/历史报告可保留具体值但须标注「设计快照/样例」；迁移期临时写死必须登记 TD 并在同次汇报给出替换计划。
  - **B11.7 违规级别**：P0 = 核心/测试写死或满矩形假设，换章节规格后无法运行/回归误报；P1 = UI/文档写死导致布局错位/信息误导/验收失效；P2 = 注释/历史文档/上限说明。


### C 类：文档与可维护性（P1/P2）

- **C1 接口同步（可机械校验）**：接口变更同步更新 `.team/archive/20261121/memo-root.md`、`STEP*_HANDOFF.md`、`magic/README.md`；文档中反引号包裹的接口名必须能在代码中 grep 到。已知过期文档在顶部加「已过期，以代码/HANDOFF 为准」横幅。
- **C2 验收映射**：
  - `magic/测试.md` 覆盖本步新增行为，验收项与 diff 一一对应；
  - **验收项引用的日志必须能在该节声明的 `debug_level` 下输出**，级别符合 A7；
  - 行为变更后，旧步骤清单必须标注「已过时」并指向新验收项。
- **C3 注释**：解释「为什么」而非「是什么」；魔法数字要有名字。
- **C4 构建同步**：新增/重命名库时同步更新 `tools/precompile_check/build_harness.py` 的 `SOURCES` / `REPLACED`。


- **C5 规格描述带「样例」限定（2026-11-17 新增）**：文档提到网格规格/房间数/边数/槽位数时，必须写成「**按章节配置；当前样例为 N×M（/ N 房 / E 边 / S 槽位）**」，不得写成固定规格。已过期的旧规格文档（如 `magic/介绍_v2.txt` 的 7×7 固定描述）须加「旧版样例，现行以章节配置为准」横幅。

### D 类：验证证据（P1/P2）

- **D1 拆线程/懒采样类改动**：验收项必须「日志行 + 行为」双写，并给出缺行排查指引（方法论 2.3 缺行法）。
- **D2 模块交付状态**：占位或未交付模块（如 `dust` 空壳）不得注册为可进入章节，必须在 HANDOFF/测试清单标注状态；`PROBE_ENABLED` 等调试开关需有发布前检查项。
- **D3 任务完成契约（2026-11-21 新增）**：每个任务/步骤结束必须留下「命令 + 输出」证据——完成前重跑验证命令、读完整输出、确认退出码与断言；偏离计划或规范必须写 `Ruling: 决定 — 理由 — 后果`（进 HANDOFF/任务板/报告）。无证据的口头完成按 P1 处理。**完成证据不得来自放宽/跳过/删除断言**；修改测试本身需作者明确授权，并说明该测试所守的不变量。验证必须作用于**被改的行为**：只证明常量/配置改对不够（倍率、取整、覆盖取值都会让行为不变或不同）；若现有回归未覆盖该行为，先补断言再宣称完成——**未覆盖该指标的 PASS 不构成证据**。
- **D4 审查分级按用户实际影响（2026-11-21 新增）**：P0/P1/P2 按「合理用户实际会得到什么后果」定级，不按「规范是否提及该输入」定级。规范沉默但用户会受损 → 按影响定级，并在报告里单独标注规范缺口；不得因「规范没写」降为 P2。

## 3. 检查节奏

| 模式 | 触发 | 范围 | 输出 |
|---|---|---|---|
| **门禁 G** | 每次代码改动后、同步 KKWE 前 | A 全量 + B7 + B10（UI 文件）+ **B11（章节规格单一数据源）** + C2 + C3（魔法数字/裸字面量检查）+ 编译 | PASS/FAIL + P0 清单 |
| **门禁 G-UI** | 新增/修改 `magic/map/ui/**` 的批次 | G 全量 + **UI规范 §10 视觉验收（美观自检）逐项 PASS** + **§10.1 交付前自评（结论 PASS + 缺陷清单 + 第一眼测试）** + token 表一致性（代码常量 ↔ 规范 §5 颜色/字号 token） | PASS/FAIL + 截图证据 + 测量值 + **自评结论** + TD 登记 |
| **门禁 G11** | 涉及章节/网格/测试/UI/文档的批次（换章节规格、改 grid/data/slot/reveal、改回归断言） | B11 全量：grep 具体规格数字（7×7/6×6/49/58/20/36）、满矩形/dense 假设、遍历无「格存在」判断、断言是否 API 自洽；新章节配置的 cell/边/参数校验 | PASS/FAIL + 违规清单（文件:行 + 级别） |
| **回归门禁 G'** | Lead 修复门禁问题后 | 仅复核修复 diff + 编译 | PASS/FAIL + 修复项关闭确认 |
| **架构复核 A** | 每个 Step 结束前 | A 抽检 + B 全量 + C/D 全量 | 复核报告 + 技术债登记 |
