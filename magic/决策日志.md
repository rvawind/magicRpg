## 2. 变更记录

### 2026-11-16：UI 分层原则确立（用户口径，关键）

- **结论**：地图面板 = **虚构层内的实体道具**（玩家手里的实体羊皮纸地图：烧边/墨绘/蜡封/罗盘/手写图例）；
  选英雄（契约对象）= **元层/系统 UI**（魔法契约），**保持原风格、不做羊皮纸化、本次不改**。
- **原则**：**同一语义层内统一材质；跨层只统一工艺**（美术精度/配色气质/字体纹饰工艺），不是互相套用材质。
- **参考方向是单向的**：地图面板参考选英雄界面的做工（边框/布局/花饰工艺）成立；反过来把地图的羊皮纸质感
  套到系统 UI 上不成立。
- **影响**：task-13「选英雄改羊皮纸版 H1~H3」作废，仅存档；task-14 改为按「实体地图」方向重做。
- **出处**：`.team/HANDOFF_20261116.md`（用户澄清 20:3x / 设计前提修正 21:0x）。

### 2026-11-21：UI 主实现从「原生 UI（Border/图层）」切到「ComfyUI 素材管线」

- **变更**：作者接入 ComfyUI 生图后，UI 元素改为生成素材（BLP）承载；原生 Border / 原生帧方案不再作为主实现。
- **原因**：素材可直接生成，视觉可控、风格统一；原生 UI 实现成本高、效果受限。
- **影响**：
  - “玩家所在格外层高亮”的实现方式改变：不必在原生帧上做 Border/图层，优先由素材表达。
  - 旧的原生 Border 实现降级为 fallback，**不得与新素材叠加使用**。
  - `UI设计规范.md` 的 token 与贴图命名需随素材管线同步（现按 v2.0 执行）。
- **待清理 / 待核实**（Lead 下一批 UI 工作处理，verifier 复核）：
  1. `magic/map/ui/gridMap.j`：确认 `CurRing` / `HoverRing` / `CellFrame` 的高亮全部走素材，无原生边框叠加；如有则改为素材高亮。
  2. `magic/map/ui/uiPick.j`：选择面板若仍用原生边框/原生装饰，评估是否改用素材。
  3. `.team/ui_design/**` 旧方案稿（v2~v5 迭代图、web_proto）里“原生 Border + 素材”混合方案标记废弃，避免后续误用。
  4. 九宫格 / 描边 / 贴图尺寸假设：与新素材实际尺寸核对，删除不再适用的常量（对照 `质量基线` C3 魔法数字检查）。
- **证据**：作者 2026-11-21 反馈（生成素材上叠原生 Border，效果诡异）；`UI设计规范.md` v2.0；`.team/screens/` 截图。

## 3. 玩家所在格高亮（目的优先）

- **目的**：玩家一眼看出自己当前所在格（最外层高亮）。
- **手段优先级（素材管线现行）**：
  1. 素材自带发光 / 描边 / 动效（首选，风格最统一）；
  2. 额外贴图 / 图层叠加（光晕、环、底垫）；
  3. 原生 Border（**仅当无素材方案时的 fallback；禁止叠在成品素材上**）。
- **失败处理**：某手段不可行时，回到“目的”重新枚举手段，不得卡在单一实现上，也不得无视前提变化继续沿用旧手段。

## 4. 使用规则

1. 新会话按 `CLAUDE.md` 的 Reading Order：本文件 → 方法论 → 计划/测试 → 交接。
2. 引入新工具、改变主实现、替换视觉方案 = **策略变更**：必须追加记录 + 写影响清单，并在交接文档中指向本文件（不重复抄写）。
3. 任务描述只给“手段”时，先写「目的 + 候选手段」，再动手；手段失败回目的枚举。
4. 动手前做前提复核：现行策略、规范版本、素材管线、废弃状态是否仍成立；前提失效要主动指出，不得默默沿用旧实现。
5. 旧方案不删，标「已废弃」+ 日期 + 取代者，保留可追溯。
