# WE 编译测试清单（分步验收）

> 本文件是分步测试记录。Claude 每完成一步会停下；你在 YDWE/WE 中按本清单编译 + 运行测试，**全部通过后再让 Claude 继续下一步**。
> 每测完一步，把「测试」列勾选并反馈结果（含报错信息/日志截图），Claude 据反馈修复或继续。

## 通用操作

- **编译**：在 YDWE 中打开地图 → 保存（Ctrl+S 触发 jasshelper 编译）→ 看「编译错误」窗口。无报错即通过。
- **运行**：测试地图（F9 或「测试地图」按钮）→ 观察游戏内左下角消息（`BJDebugMsg`）。
- **日志级别**：`debug.j` 中 `debug_level` 当前为 `0`，因此 `[DEBUG]/[INFO]/[WARN]/[ERROR]` 都显示；高频过程日志（逐只刷怪、逐单位区域进出）为 `[TRACE]`（-1），默认不显示。
- **排查原则**：不要靠把 `debug_level` 调到 `-1` 来排查（会淹没信号）。预期内的关键结果用 INFO，**不变量被破坏的异常状态用 WARN**（默认可见）。例如：
  - `[room] spawn produced 0 monsters ...`：房内有玩家、未清空却刷出 0 只（游标/池异常）；
  - `[room] leave removed N/M monsters ...`：离场应删 M 只实际只删到 N 只。
  只有确实需要看逐条细节时，才临时把 `debug_level` 设为 `-1`。正式发布前改回 `1`。

### 1.1 编译

### 1.2 运行时
- [ ] **未清房禁止移动**：进入一个怪物房（不清空），走到出口矩形 → 不开始引导；开 `debug_level=0` 后应看到 `[exit] channel blocked`；角色仍在房内。
- [ ] **清房判定**：杀光该房怪物 → 看到 `[room] room cleared`（INFO，默认可见）。
- [ ] **清房后特效切换**：清房后，该房出口特效从红色（DoomTarget）切换为传送门（MassTeleportTo）。
- [ ] **清房后传送**：清房后走进出口矩形 → 开始引导（`[exit] channel started`）→ 约 3s 后传送（`[exit] teleport complete`）到目标房。
- [ ] **安全区/入口直达**：在入口房或安全房，走进出口矩形 → 快速通道（约 0.5s）即可传送。
- [ ] **可配置时长（可选）**：在 `forest.j` 的 `InitForest` 临时加 `call SetAreaExitDelay(5.0)`，普通房引导变 5s，验证后移除。

## Step 2：紧急穿越技能 + 怪物池持久化

### 2.1 编译
- [ ] 保存无报错（涉及 `emergency.j` 新增、`chapter.j` 的 include、`forest.j` 的 `SetEmergencyAbilityId`）。
- [ ] 确认跨库函数 `areaEmergency_SetEmergencyAbilityId`、`ResetAreaEmergency` 能解析（无「未定义函数」报错）。

### 2.2 前置配置（物体编辑器，必须）
- [ ] 为所有英雄添加一个**共通技能**：无目标、瞬发（可基于 Berserk/狂战士 这类无目标瞬发技能制作），技能原始 ID 设为 `'A07E'`。
  - 若你用的是别的 ID，请同步改 `forest.j` 里 `areaEmergency_SetEmergencyAbilityId('A07E')` 的实参。

### 2.3 运行时
- [ ] **正常代价穿越**：未清房时站在方向矩形上施放紧急穿越 → 扣当前生命 20%，瞬时传送到相邻房；日志 `[emergency] traverse X -> Y`（INFO）。
- [ ] **濒死免费**：生命 <30% 时施放 → 不扣血，进入冷却；日志中 `cd=10.0`。
- [ ] **冷却限制**：冷却期内再次施放 → 无效；开 `debug_level=0` 应看到 `[emergency] cooldown active`。
- [ ] **怪物池持久化**：紧急穿越离场后，原房怪物被删除并把未击杀数量退回池子（日志 `[room] player leave X count->0` + `[room] all players left X -> remove N monsters, rewind cursor`）；再次进入原房 → 重新刷出未击杀的怪物（`[room] SpawnDelay ... spawned=` 非 0）；已击杀的怪物不会被重复刷出。
- [ ] **重复进出同一怪物房**（回归）：H → I（刷怪）→ 紧急穿越到 J → 紧急穿越回 H → 再次 H → I，**I 必须重新刷怪**；若 I 的离开记账丢失，日志会缺少 `[room] player leave I count->0`，且再次进入只显示 TRACE 级 `skip: player already marked present`。
- [ ] **走上出口矩形不误删**：未清房时走进火焰特效（出口矩形），怪物不应消失；日志只应出现 `[room] leave ignored (clamped back)`（TRACE，默认不显示）。
- [ ] **异常告警**：正常流程中不应出现任何 `[WARN]`。若出现 `spawn produced 0 monsters` 或 `leave removed N/M monsters`，说明游标/计数确实异常，需修复代码而不是调日志级别。
- [ ] **重置**：关卡切换后，紧急穿越冷却被清空（新关内可立即施放）。

## Step 3：7×7 网格 + 物理槽位池

### 3.1 前置配置（WE 区域，必须）

在区域面板创建 **21 个矩形**，名称必须完全一致（Claude 已在 `forest.j` 中引用）：

```
gg_rct_FR_A1 .. gg_rct_FR_A5    // 地形 A
gg_rct_FR_B1 .. gg_rct_FR_B5    // 地形 B
gg_rct_FR_C1 .. gg_rct_FR_C5    // 地形 C
gg_rct_FR_D1 .. gg_rct_FR_D5    // 地形 D
gg_rct_FR_BOSS                  // BOSS 预留槽
```

- 每个矩形是一个完整房间的**活动区域**；房间之间必须留出间隔，矩形**不能重叠**
  （重叠会导致进出事件互相干扰，玩家被守卫来回拉回）。
- **不要**创建门洞/出口矩形：4 个方向的门洞矩形由 `forest.j` 按房间边缘自动生成。
- 旧的 `gg_rct_Forest_*` / `gg_rct_Forest_Exit_*` 不再被引用，保留不影响编译与运行。
- 地形 A/B/C/D 的装饰差异属 Step 4（线框层/特效），本步只验证功能。

### 3.2 编译
- [ ] 保存地图无 jasshelper 报错。
- [ ] 若报「未定义变量 `gg_rct_FR_*`」，说明 3.1 的矩形缺失或名称拼写不一致。
- [ ] 无「未定义函数 `Area_EnsureBound` / `ResetAreaEnter`」一类前向引用报错。

### 3.3 启动日志（`debug_level = 0`）

- [ ] 出现 21 次 `[slot] registered slot=N terrain=T region=(x,y)`（terrain 依次为 0..3 各 5 次，最后一次 -1）。
- [ ] `[forest] physical rooms registered: slots=21 terrains=4`。
- [ ] `[grid] BuildEdges done: 7x7 cells=49 edges=E prune=0.300`；`E` 在 **48 ~ 84** 之间（生成树 48 条 + 额外边）。
- [ ] `[slot] acquired boss logical=R` —— BOSS 逻辑房开局即绑定预留槽位。
- [ ] `[forest] InitForest done: chapter=... enter=(r,c) boss=(r,c) slots=21`：
      `enter` 在外围（row=0/6 或 col=0/6），`boss` 属于 `{(2,2),(3,3),(4,4)}`。
- [ ] 全程无 `[WARN]`（尤其不应出现 `[area] terrain unassigned`、`[slot] acquire failed`）。

### 3.4 起点与入口绑定
- [ ] 补给时间结束后，全部英雄被传送到入口房。
- [ ] 日志 `[slot] acquired logical=... slot=...`：入口逻辑房首次绑定时分配同地形槽位。
- [ ] 入口房 4 个方向中：有邻接的显示蓝色传送门特效（MassTeleportTo），被剪枝或越界的方向无特效。
- [ ] 从入口房向外走、试图越过房间边界 → 被拉回房内（行为与 Step 1/2 一致）。

### 3.5 未清房时封锁
- [ ] 进入怪物房后清房前，门洞特效应为红色封锁（DoomTarget）。
- [ ] 走进封锁门洞不会传送；临时把 `debug_level` 设为 `-1` 可看到 `[exit] blocked (room not cleared)`。
- [ ] 未清房时使用紧急穿越仍可传送（Step 2 行为回归）：`[exit] emergency teleport (r,c)->(r',c')`。

### 3.6 清房后瞬时传送
- [ ] 杀光怪物 → `[room] room cleared`，门洞特效由红变蓝，祭坛生成。
- [ ] 走进任一门洞 → **立即**传送（无 3 秒引导），日志 `[exit] teleport (r,c)->(r',c') slot=N`。
- [ ] 传送落点为目标房中心，目标房内容（怪物/祭坛/安全区）与逻辑房类型一致。
- [ ] 安全区/入口房无需清怪即可直接传送。

### 3.7 槽位回收与粘性复用
- [ ] 离开一个 CLEARED 房间且房内无玩家，约 1 秒后出现
      `[enter] release idle room (r,c) slot=N state=2` + `[slot] released logical=...`，
      该物理房的门洞特效被清除。
- [ ] 物理房被回收后，逻辑房数据仍在：再次进入同一逻辑房仍显示 `CLEARED`，
      且日志出现 `[forest] respawn altar for reacquired cleared room`，祭坛重新生成。
- [ ] 粘性绑定：同一逻辑房再次进入时，若它上次使用的物理房仍空闲且地形一致，
      日志中的 `slot=` 与上次相同。
- [ ] `[slot] released` 只发生在物理层，**逻辑坐标不会消失**（房间类型/状态不会被重置）。

### 3.8 ACTIVE 保留
- [ ] 未清房时用紧急穿越离开，房间保持 ACTIVE，**不**出现 `release idle room`。
- [ ] 离场时日志 `[room] all players left (r,c) -> remove N monsters, rewind cursor`，房内怪物被删除。
- [ ] 再次进入时从断点继续刷怪（不会重复刷已击杀的怪物）。

### 3.9 槽位溢出驱逐（可选，较难触发）
- [ ] 同地形 5 个槽位全被占用时，分配会优先驱逐「无玩家、非 BOSS、非诅咒、CLEARED/INACTIVE」的房间，
      日志 `[slot] overflow: evict logical=... from slot=... for logical=...`。
- [ ] 被驱逐房间之后重新进入时能正常重建祭坛与门洞。

### 3.10 BOSS
- [ ] BOSS 逻辑房始终使用 `gg_rct_FR_BOSS` 预留槽，不会被普通房间挤占。
- [ ] 首次进入 BOSS 房生成 BOSS；击败后生成奖励祭坛（应为最高等级，tier 3），并完成关卡。
- [ ] 关卡完成后 `[slot] ResetAreaSlot done`，进入下一关时再次打印
      `[grid] BuildEdges done` 与 `[forest] InitForest done`，槽位绑定全部从零开始。

### 3.11 回归
- [ ] Step 1/2 已通过的项全部复测一遍（清房判定、怪物池持久化、紧急穿越代价/冷却）。
- [ ] 正常流程中不应出现任何 `[WARN]`。
