## 1. Code Conventions

- **Library names**: camelCase only (e.g., `library areaMonsterRoom requires MonsterGroup`). No underscores.
- **Variable names**: `udg_` prefix is forbidden for code we declare. **Exception**: WE GUI 生成的 `udg_*` 全局（如 `udg_Hero`）允许引用，但需注释说明来源。
- **Include pattern**: 每个 `.j` 自带 header guard，`#include` 外层不要再包 `#ifndef`；`#endif` 后若同文件还有代码需空一行（文件以 `#endif` 结尾则不加）：
```jass
#ifndef YDWEYDWEJapiScriptIncluded
#define YDWEYDWEJapiScriptIncluded
#include "japi\\YDWEJapiScript.j"
#endif
```
- **Forward references**: vJass 单遍扫描，函数/`function X` 句柄必须定义在调用点之前。`code`/`type`/`function` 是保留字，不能作变量名。
- **Cross-library calls**: `public function` 编译后带 `LibraryName_` 前缀（如 `MonsterGroup_GetGroupEntryCount`）。
- **Memory cleanup**: 创建型句柄（`unit`/`group`/`timer`/`effect`/`trigger`）函数末尾置 `null`，不再使用的 `trigger`/`timer` 要销毁；**重复初始化路径不得每次重建常驻句柄**。
- **Logging**: `DebugLogger_Log(LOG_TRACE/DEBUG/INFO/WARN/ERROR, msg)`；TRACE=高频过程（`debug_level=0` 不显示）、INFO=低频结果、WARN=不变量被破坏。不要用 `debug_level=-1` 作为排查手段。
- **单线程字节码上限约 30 万条**：初始化逻辑禁止逐房 BFS/O(N²)，批量查询用距离场，大循环分批或 `TriggerExecute` 拆线程。

## 3. Room System

**Room types**: `ROOM_TYPE_MONSTER`(0), `ROOM_TYPE_SAFE`(1), `ROOM_TYPE_BOSS`(2), `ROOM_TYPE_ENTRY`(3), `ROOM_TYPE_ELITE`(4), `ROOM_TYPE_MERCHANT`(5)

**Room states**: `ROOM_STATE_INACTIVE`(0), `ROOM_STATE_ACTIVE`(1), `ROOM_STATE_CLEARED`(2), `ROOM_STATE_CURSED`(3)

**Room type distribution**（`InitAreaWithEnter(chapterId)`）:
1. Guarantee minCount for registered types (skip BOSS/entry/assigned)
2. Mark entry areas as `ROOM_TYPE_ENTRY`
3. Remaining areas use decaying weight random assignment
4. Monster room fallback (default weight 700)

**Decaying weight**: `effectiveWeight = weight × (maxCount - assignedCount) / maxCount`

## 4. Initialization Order（Forest 当前样例；下列数字均为样例，规格按章节配置）

1. 物理房注册（只做一次）：`areaSlot_RegisterPhysicalRoom(terrain, rect, doorUp, doorDown, doorLeft, doorRight)` ×20
2. 逻辑网格：`Grid_Init(7,7)` → `Grid_SetGeneratorMode` / `Grid_SetExtraEdgeBudget(10)` / `Grid_SetBraidChance(0.60)` → `Grid_BuildEdges()`（48 树边 + 10 额外 = 58 边）
3. 注册逻辑房：`RegisterArea(areaId)` ×49（areaId = row*7+col）
4. 起点/BOSS 候选：`AreaAddPeripheralEnters()`（外围 8 格）→ `AreaAddBossCandidate((2,2)/(3,3)/(4,4))` → `RollBossArea()`
5. `TriggerExecute(InitForestStage2)`（新线程重置字节码预算，同步执行）：
   `AreaSetEntryBossMinDistance(8)` → `RollActiveEnter(chapterId)` → `RegisterRoomType`/`SetRoomTypeWeight` → `InitAreaWithEnter(chapterId)` → `InitAreaGuards()` + `InitAreaExits()` → 怪物组 + `InitMonsterRoom()` → `InitBossSystem()` / `ChapterTimer` / `CurseSystem` / `RewardAltar` / 紧急技能 ID
6. 关卡注册：`ChapterManager_RegisterChapter("Forest", 600)` + `SetChapterInitFunc(chapterId, function InitForest)`

**注意**：`InitMonsterRoom()` 必须在 `InitAreaWithEnter()` 之后；BOSS 中转房不预留物理槽位、不刷怪。

## 7. Hashtable Keys

**各模块自己持有 hashtable 与键常量**（如 `data.j` 的 `HT_ROOM_TYPE`、`monster_room.j` 的 `HT_SPAWN_CURSOR/HT_SPAWN_REMAIN`），定义在文件顶部 `private constant integer HT_*`。
- 区域属性：parent key = areaId，subkey 1-8（类型/状态/怪物池/cap/外围/存活/已清/地形）+ 50/51（刷怪游标）
- 全局配置：parent key = 0，subkey 200-210；列表在 300/400/500/600/800/900

## 8. Forest Level（当前样例；规格按章节配置）

**当前代码样例值**（按章节配置：可 5×4/6×6/稀疏/不规则）：7×7 逻辑网格（49 逻辑房，logicalId = row*7+col）+ 20 物理槽位房（4 地形 A/B/C/D × 5）。
生成器：DFS 生成树 + 10 条额外边预算（死路 braid 概率 0.60）= **58 条边**；入口→BOSS 图距离目标 **8**。
物理房矩形：`gg_rct_FR_A1..A5 / B1..B5 / C1..C5 / D1..D5`；门洞模板：`gg_rct_FR_{A,B,C,D}_DOOR_{UP,DOWN,LEFT,RIGHT}`。旧 `gg_rct_Forest_*` 未使用。
起点：外围 8 格（4 角 + 4 边中点）抽 1；BOSS 候选：逻辑 (2,2)/(3,3)/(4,4) 抽 1；BOSS 中转房不刷怪。
地形装饰差异属后续步骤，不在 Step 3/4 范围。
